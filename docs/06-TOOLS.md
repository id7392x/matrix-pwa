## 1. Что такое MCP и зачем

MCP — живые источники **внешнего** знания: документация библиотек, макеты UI.
Они НЕ заменяют `docs/00–05`: те отвечают «что должно быть в проекте и почему»,
MCP — «как сейчас работает библиотека X». Проектные инварианты, архитектура,
DTO, правила — берутся **только** из `docs/*.md` и `AGENTS.md`.

## 4. Правила

1. MCP/внешние доки = только ВНЕШНЕЕ знание. Проектные решения — только `docs/*.md`.
2. Расхождение `docs/*.md` ↔ внешние доки → приоритет у `docs/*.md`; расхождение зафиксировать в `HANDOFF.md`.
3. Stitch-макеты = референс. Реализация только вручную: Svelte 5 Runes + Tailwind, сгенерированный HTML/CSS не копипастить.
4. Сверку по E2EE/verify-UX делать с element-web (§3) и `docs/05-UI-E2EE.md`, не наоборот.

## 5. Цикл дизайна (DESIGN.md ↔ макеты)

1. `DESIGN.md` фиксирует проблемы существующего UI (факты о коде).
2. Внешние макеты (Stitch/скриншоты) — гипотезы решения.
3. Выбрать вариант → реализовать компонент по правилам слайса (TDD, токены DESIGN.md Phase 1).
4. Обновить `DESIGN.md` (статус, замечания).

## 6. Stitch: рецепты и статус дизайн-трека

### 6.1. Рецепты (проверено 2026-08-30)

- **Модель генерации:** всегда `modelId: GEMINI_3_1_PRO` (Gemini Pro). Flash/дефолт дают мелкие артефакты в макетах («косяки»); Pro — заметно чище.
- **По одному экрану за раз.** Пачка генераций подряд может не зарегистрироваться (`updateTime` застревает). После каждого вызова — поллинг `list_screens`/`get_project`, пока не появится новый экран.
- **Таймаут = норма.** `generate_screen_from_text`/`edit_screens`/`generate_variants` падают по MCP-таймауту (~120 c), но результат долетает фоном за ~5-6 мин. НЕ ретраить сразу — проверять поллингом.
- **Удаления экранов нет** (`delete_screen` отсутствует в MCP; в stitch-вебе тоже нельзя). Мусорные экраны — игнорировать. Чистый проект = создать новый (`stitch_create_project`) и перегенерировать — текущие макеты при этом потеряются.
- Дизайн-систему (`designSystem`-ассет) тоже нельзя удалить; её можно пересоздать (`create/update_design_system`) — это меняет стиль дальнейших генераций, но не трогает уже сгенерированные.
